**pipeline.ts** — TypeScript pipeline orchestrator.

Exports:
- `runAnalysisPipeline(db: Database.Database): Promise<PipelineResult>`
- `getNextAnalysisDate(): Date`

```typescript
interface PipelineResult {
  success: boolean;
  steps: StepResult[];
  totalDurationMs: number;
  digestSent: boolean;
}
interface StepResult {
  step: string;
  status: "success" | "failed" | "skipped";
  durationMs: number;
  signalsProcessed?: number;
  signalsSkipped?: number;
  error?: string;
}
```

Implementation:
1. **getNextAnalysisDate()**: Calculate next 25th at 02:00 UTC. If current date >= 25th of current month, return 25th of next month. Handle month rollover correctly.

2. **runAnalysisPipeline(db)**: Execute pipeline in STRICT sequence (per locked decision):
   - Step 1: `analyze_stationarity` — run always
   - Step 2: `analyze_granger` — run only if Step 1 succeeded (stationarity is hard gate for Granger)
   - Step 3: Cross-correlation is integrated into analyze_granger.py (STAT-04), no separate step needed
   - Step 4: `analyze_composite` — run only if Step 2 succeeded (needs granger_results)
   - Step 5: `analyze_anomalies` — run always (independent of Granger)
   - Step 6: `analyze_affordability` — run always (independent of Granger)
   - Step 7: `analyze_expat_funnel` — run always (independent of Granger)

3. For each step:
   a. Log start to analysis_log via prepared statement: `db.prepare("INSERT INTO analysis_log (pipeline_step, status, signals_processed, signals_skipped, duration_ms, error, run_at) VALUES (?, 'in_progress', 0, 0, 0, NULL, datetime('now'))").run(stepName)` (SEC-06)
   b. Call `runPython(scriptName, {db_path: dbPath}, {defaultTimeoutMs: 300_000})` — 5 minute timeout for batch operations (research pitfall #5)
   c. On success: update analysis_log with status='success', populate signals_processed/skipped from Python output
   d. On failure: update analysis_log with status='failed', sanitize error (strip any numeric sequences that could be data — SEC-07), set dependent steps to 'skipped'
   e. Record StepResult

4. **DB path resolution**: The db path must be passed to Python modules. Resolve from DB instance — better-sqlite3 provides `db.name` property. Pass as `{db_path: db.name}` to runPython.

5. **Cache update**: After pipeline completes, update intelligence_cache TTL for all analysis products. `expires_at` = getNextAnalysisDate().toISOString(). Use prepared statements for all updates (SEC-06).

6. **Digest dispatch** (after all steps complete):
   a. Count significant Granger signals: `SELECT COUNT(*) FROM granger_results WHERE significant = 1 AND tested_at > datetime('now', '-1 day')`
   b. If count >= 3: call `generateDigest(db)` from digest.ts, then send via Telegram (using existing bot integration pattern)
   c. If count < 3: skip digest, log "insufficient validated signals for digest" to analysis_log (research pitfall #8)

interface DigestData {
  compositeScore: { score: number; zone: string; componentCount: number };
  topMovers: Array<{ area: string; score: number; change: number }>;
  newGrangerSignals: Array<{ source: string; target: string; lag: number }>;
  anomaliesDetected: Array<{ source: string; metric: string; zScore: number }>;
  funnelSummary: string;
}
```

Implementation:
1. **generateDigest(db)**:
   - Read latest city-wide composite: `SELECT score, zone, component_count FROM composite_scores WHERE area = 'dubai' ORDER BY computed_at DESC LIMIT 1` (parameterized if needed, but 'dubai' is a constant here)
   - Read top 5 area movers: `SELECT area, score FROM composite_scores WHERE area != 'dubai' ORDER BY computed_at DESC LIMIT 20` then compare to previous run to find biggest changes
   - Read new Granger signals: `SELECT signal_source, signal_metric, target, best_lag FROM granger_results WHERE significant = 1 AND tested_at > datetime('now', '-32 days') ORDER BY pvalue ASC LIMIT 5` (parameterized)
   - Read recent anomalies: `SELECT source, metric_name, z_score FROM anomaly_flags WHERE flagged_at > datetime('now', '-32 days') ORDER BY ABS(z_score) DESC LIMIT 5` (parameterized)
   - Read funnel digest: `SELECT result_json FROM intelligence_cache WHERE cache_key = 'expat_funnel_latest'` → parse, extract digest_text

   ANOMALIES DETECTED:
   - [source] [metric]: [direction] (z=[zScore])

   [funnelSummary]
   ```
