   - metric_name TEXT NOT NULL
   - adf_statistic REAL
   - adf_pvalue REAL
   - kpss_statistic REAL

   - id INTEGER PRIMARY KEY AUTOINCREMENT

   - best_lag INTEGER
   - f_statistic REAL
   - pvalue REAL
   - bonferroni_alpha REAL
   - significant INTEGER NOT NULL DEFAULT 0
   - weight REAL (1/pvalue if significant, 0 otherwise)

   - signals_skipped INTEGER
   - duration_ms INTEGER
   - error TEXT (sanitized — no raw data values)
   - run_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP

**analyze_stationarity.py** — Batch mode stationarity testing with auto-differencing and direct DB write.

Bridge pattern input (JSON stdin): `{"db_path": "/opt/lobsec/data/uae-re.db"}`
Bridge pattern output (JSON stdout): `{"processed": int, "skipped": int, "results": [{"source": str, "metric": str, "verdict": str, "differenced": bool}]}`

Implementation:
1. Connect to SQLite at db_path using sqlite3 stdlib
2. Query `SELECT DISTINCT source, metric_name FROM normalized_monthly` to discover all (source, metric) pairs
3. For each pair, fetch values: `SELECT value FROM normalized_monthly WHERE source = ? AND metric_name = ? ORDER BY measurement_date ASC` (parameterized SQL — SEC-06)
4. Filter out NULL values. If fewer than 12 observations, skip and log "insufficient data"
5. Call existing `test_stationarity(series)` from `stationarity.py`
6. **Auto-differencing** (per locked CONTEXT.md decision): If verdict is "non-stationary" and len(series) >= 13:
   - Compute first differences: `[series[i] - series[i-1] for i in range(1, len(series))]`
   - Retest with `test_stationarity(differenced_series)`
   - If still non-stationary after differencing, log as "non-stationary" with differenced=True
   - If now stationary, log as "stationary" with differenced=True
7. Write each result to stationarity_results table: `INSERT OR REPLACE INTO stationarity_results (source, metric_name, adf_statistic, adf_pvalue, kpss_statistic, kpss_pvalue, verdict, differenced, obs_count, tested_at) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, datetime('now'))` — all parameterized (SEC-06)
8. Write analysis_log entry: `INSERT INTO analysis_log (pipeline_step, status, signals_processed, signals_skipped, duration_ms, run_at) VALUES ('stationarity', ?, ?, ?, ?, datetime('now'))` — metadata only, no PII (SEC-07)
9. Commit and close connection
10. Output summary JSON to stdout

**analyze_granger.py** — Batch Granger causality with Bonferroni correction, cross-correlation, and DB write.

Bridge pattern input (JSON stdin): `{"db_path": "/opt/lobsec/data/uae-re.db"}`
Bridge pattern output (JSON stdout): `{"tested": int, "significant": int, "skipped": int, "results": [{"signal": str, "target": str, "significant": bool, "best_lag": int, "pvalue": float}]}`

Implementation:
1. Connect to SQLite at db_path
2. Identify Tier A+B signal (source, metric) pairs by querying `stationarity_results` for signals with verdict = 'stationary' (or 'stationary' after differencing). Per locked decision: only Tier A+B signals (not Tier C).
   - Tier A sources: ejari, permits, adrec, bayut, propertyfinder, dewa
   - Tier B sources: mohre, dxb, gdrfa, khda, rta, jobs, salary, remittances
   - Exclude `dld` source metrics that ARE the targets (meter_sale_price, trans_count)
3. Define two target series: dld/meter_sale_price (price) and dld/trans_count (volume). Fetch from normalized_monthly with parameterized SQL
4. **Bonferroni correction scope** (CRITICAL — research pitfall #2): Calculate N_total = number of valid (signal, target) pairs BEFORE the test loop. Alpha = 0.05 / N_total. With ~40 tests, alpha ~= 0.00125.
5. For each valid signal vs each target:
   a. Fetch both series from normalized_monthly, aligned by measurement_date (INNER JOIN on date)
   b. If aligned length < 12 observations, skip
   c. Check stationarity from stationarity_results. If non-stationary, apply first-differencing to BOTH signal and target series
   d. If still non-stationary after differencing, skip the pair and log
   e. Run `grangercausalitytests()` from statsmodels with maxlag=12. Catch exceptions gracefully
   f. Extract best lag (lowest p-value across lags 1-12)
   g. Determine significance: best_pvalue < bonferroni_alpha
   h. Compute weight: `1.0 / pvalue` if significant, else 0.0
   i. **Cross-correlation** (STAT-04): For significant signals, run scipy.stats.pearsonr at lags 1-12 to find optimal lag. Store this as the cross_correlation_lag
6. Write each result to granger_results table with parameterized SQL
7. Write analysis_log entry (metadata only — SEC-07: log signal count and p-value range, NOT individual visa/salary data points)
8. Commit and close connection
9. Output summary JSON to stdout
