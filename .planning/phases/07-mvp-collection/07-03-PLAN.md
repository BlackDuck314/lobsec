  <action>
    1. **ADRECAbuDhabiCollector** (adrec-abu-dhabi.ts):
       - Extend SourceCollector with metadata: `{source: "adrec-abu-dhabi", frequency: "monthly", priority: 2, timeout: 300_000}` (5 min for browser automation)
       - `collect()` implementation:
         a. Launch Playwright chromium in headless mode
         b. Create context with `acceptDownloads: true`
         c. Navigate to `https://adrec.gov.ae/en/property_and_index/adrec-dashboard`
         d. Wait for `networkidle` load state
         e. **Set broadest filters**: The dashboard has filters (Asset Type, District, Project, Layout, currency, period). Clear any default filters or select "All" options to export the maximum dataset. Use `.selectOption()` for dropdowns or `.click()` for checkboxes/buttons. Exact selectors must be determined during implementation — inspect the dashboard DOM.
         f. **ADREC has multiple dashboard sections** (Transactions, Residential Leases, Price Indices, Recent Sales). Collect from the **Transactions** section first (most critical). If the dashboard uses tabs, click the Transactions tab first.
         g. Trigger CSV export: `const downloadPromise = page.waitForEvent('download');` then click the export/download button. Common selectors to try: `button:has-text("Export")`, `button:has-text("Download")`, `a:has-text("CSV")`, `button[aria-label*="export"]`.
         h. `const download = await downloadPromise;`
         i. Save with `download.saveAs(filePath)` to `/opt/lobsec/data/raw/adrec-abu-dhabi/{YYYY-MM-DD}-transactions.csv`
         j. Read file to count rows
         k. **Repeat for Residential Leases** section (if different tab/section) — save as `{YYYY-MM-DD}-leases.csv`
         l. **Repeat for Price Indices** section — save as `{YYYY-MM-DD}-indices.csv`
         m. Close browser in `finally` block
         n. Insert raw source metadata for each file
         o. Return `{filePath: transactionsFilePath, rowCount: totalRowCount}` (primary file is transactions)
       - **Fallback strategy**: If export button not found after 10s wait, try alternative selectors. If download doesn't start within 30s, throw descriptive error with page screenshot saved to `/opt/lobsec/logs/adrec-debug-{timestamp}.png` for debugging.
       - **Per research pitfall #1**: Always use `download.saveAs()` immediately, never rely on `download.path()`.

    2. **schemas/adrec_schema.py** — pandera schema:
       - ADREC fields per CONTEXT.md: Asset Type, Property Type, Sale Type (Off-plan/Ready), District, Community, Project, Layout (bedrooms), Registration Date, Sold Area (sqm), Plot Area (sqm), Rate (AED/sqm), Price (AED), Share, Sequence (Primary/Secondary)
       - Schema should match these columns (exact names TBD from actual CSV headers)
       - coerce=True for type flexibility

    3. **normalize_adrec.py** — ADREC normalization:
       - Read `{filePath, source, collectedAt}` from stdin
       - Load transactions CSV, validate schema
       - Aggregate by `(district, property_type, sale_type)` per month:
         - `volume` = transaction count
         - `median_price` = median of Price
         - `rate_per_sqm` = median of Rate
         - `total_value` = sum of Price
       - Compute off-plan vs ready split: percentage of transactions per sale_type
       - Compute primary vs secondary split: percentage per Sequence
       - If lease file exists (passed in input), also normalize leases:
         - lease_volume, average_rent by district
       - If indices file exists, extract price index values
       - Output as metric_name: `{district}|{property_type}|{sale_type}|{metric}`
       - Include available_date = collectedAt per NORM-02

       - Extend SourceCollector with metadata: `{source: "bayut-listings", frequency: "weekly", priority: 3, timeout: 600_000}` (10 min for comprehensive scrape across many areas)
       - `collect()` implementation:
         a. Launch Playwright chromium headless with stealth options:
            - Realistic user agent: `'Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36'`
            - Viewport: `{width: 1920, height: 1080}`
         b. Query area_names table for all Dubai areas (emirate='dubai')
         c. For each area, construct Bayut URL: `https://www.bayut.com/for-sale/property/dubai/{area-slug}/`
            - area-slug: lowercase canonical name with spaces replaced by hyphens (e.g., "dubai-marina", "jumeirah-village-circle")
         d. Navigate to area page, wait for networkidle
         e. Extract listing data via `page.evaluate()` or Playwright locators:
            - Total listing count (usually shown as "X properties for sale in ...")
            - Individual listing cards: price, bedrooms, sqft, listing date/DOM if visible, property type
            - If pagination exists, scrape first page only for MVP (full pagination deferred)
         f. **Anti-bot measures** (per research pitfall #6):
            - Random delay between areas: `Math.random() * 2000 + 1000` ms (1-3 seconds)
            - If page returns 403 or shows CAPTCHA, log warning to stderr, skip area, continue with remaining areas
            - Do NOT retry immediately on block — it makes it worse
         g. Save aggregated data as JSON: `/opt/lobsec/data/raw/bayut-listings/{YYYY-MM-DD}.json`
            - Format: `{scrapedAt, areas: [{area, listingCount, listings: [{price, bedrooms, sqft, type}]}]}`
         h. insertRawSource, return {filePath, rowCount: total listings across all areas}
       - Close browser in `finally` block

    2. **PropertyFinderListingsCollector** (propertyfinder-listings.ts):
       - Extend SourceCollector with metadata: `{source: "propertyfinder-listings", frequency: "weekly", priority: 3, timeout: 600_000}`
       - Same pattern as Bayut but different URLs: `https://www.propertyfinder.ae/en/buy/dubai/{area-slug}.html`
       - Same stealth options and anti-bot measures
       - Same JSON output format for consistent normalization
       - Save to `/opt/lobsec/data/raw/propertyfinder-listings/{YYYY-MM-DD}.json`

    **Shared concerns for both listing collectors:**
    - Both collectors are registered INDEPENDENTLY in CollectorRegistry (per user decision)
    - Each can fail without affecting the other
    - Geographic scope: ALL Dubai areas from area_names table (per user decision "all Dubai areas")
    - If blocking is severe, start with top 20 areas (per research open question #2). Add a configurable `maxAreas` parameter with default of null (all areas). Area ordering: alphabetical from area_names table, or by priority if we add a priority column later.

    3. **schemas/listings_schema.py** — Shared pandera schema for both Bayut and PropertyFinder:
       - Validate the JSON structure has required fields: area (str), listingCount (int >= 0), listings array
       - Per-listing validation: price (float >= 0), type (str)
       - Generous with optional fields (bedrooms, sqft, DOM may not always be scrapable)

    4. **normalize_bayut.py** — Bayut normalization:
       - Read `{filePath, source, collectedAt}` from stdin
       - Load JSON file
       - Per area, compute:
         - `active_listing_count` = total listings found
         - `median_asking_price` = median of listing prices
         - `median_dom` = median days on market (if available — Bayut may show listing date, compute DOM from scrape date)
         - `price_reduction_count` = count of listings with reduced price tag (if detectable from DOM)
       - Output metric_name: `{area}|{property_type}|{metric}` or `{area}|all|{metric}` for area-level aggregates
       - Resample to monthly (ME) if scraped multiple times in a month

    5. **normalize_propertyfinder.py** — Same logic as Bayut but reads from propertyfinder raw JSON:
       - Identical metric outputs for cross-validation capability
       - source = "propertyfinder-listings"
