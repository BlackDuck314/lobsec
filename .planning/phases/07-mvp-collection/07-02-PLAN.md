    **TypeScript Collectors:**

    1. **DLDSalesCollector** (dld-sales.ts):
       - Extend SourceCollector with metadata: `{source: "dld-sales", frequency: "weekly", priority: 1, timeout: 120_000}`
       - `collect()` implementation:
         a. Download CSV from Dubai Pulse: `https://www.dubaipulse.gov.ae/data/dld-transactions/dld_transactions-open` via `fetch()`
         b. If HTTP error, throw with status code
         c. Save full CSV to `/opt/lobsec/data/raw/dld-sales/{YYYY-MM-DD}.csv`
         d. Create directory recursively with `fs.mkdir({recursive: true})`
         e. Count rows (split by newlines, subtract 1 for header)
         f. Call `insertRawSource(db, {source: "dld-sales", filePath, collectedAt: new Date().toISOString(), rowCount})`
         g. Return `{filePath, rowCount}`
       - NOTE: DLD and Ejari come from the SAME CSV (per user decision). DLD collector saves the full file. Ejari collector can re-download or share the file. Since collections may run at different times, each downloads independently for simplicity.

    2. **EjariRentalsCollector** (ejari-rentals.ts):
       - Extend SourceCollector with metadata: `{source: "ejari-rentals", frequency: "weekly", priority: 1, timeout: 120_000}`
       - `collect()` implementation:
         a. Download SAME CSV from Dubai Pulse (same URL as DLD)
         b. Save to `/opt/lobsec/data/raw/ejari-rentals/{YYYY-MM-DD}.csv`
         c. Count rows, insertRawSource, return result
       - The filtering by `trans_group_en=Rent` happens in the Python normalization module (not in the collector). Collector downloads full file, normalization filters.

    **Python Schemas (pandera):**

    3. **schemas/__init__.py** — Empty file or minimal docstring.

    4. **schemas/dld_schema.py** — pandera DataFrameSchema for DLD transactions:
       ```python
       import pandera as pa
       from pandera import Column, DataFrameSchema

       dld_schema = DataFrameSchema({
           "trans_group_en": Column(str, pa.Check.isin(["Sales", "Mortgage", "Gift", "Rent"])),
           "actual_worth": Column(float, pa.Check.ge(0), nullable=True),
           "meter_sale_price": Column(float, pa.Check.ge(0), nullable=True),
           "prop_type_en": Column(str, nullable=True),
           "area_name_en": Column(str, nullable=True),
           "rooms_en": Column(str, nullable=True),
           "procedure_name_en": Column(str, nullable=True),
           "trans_date": Column(str),  # Date string
       }, coerce=True)  # coerce=True to handle string/int type variations in CSV
       ```
       NOTE: Use `coerce=True` because CSV data types are often strings. Be generous with nullable=True for optional fields. The critical validation is column existence and trans_group_en values.

    5. **schemas/ejari_schema.py** — Same schema as DLD (same source CSV) but can be a separate file for clarity:
       ```python
       from .dld_schema import dld_schema as ejari_schema
       ```

    **Python Normalization Modules:**

    6. **normalize_dld.py** — DLD sales normalization:
       - Read `{filePath, source, collectedAt}` from stdin
       - Load CSV with `pd.read_csv(filePath)`
       - Validate with dld_schema (hard error on failure per NORM-04)
       - Filter to sales only: `df[df["trans_group_en"] == "Sales"]`
       - Parse dates: `pd.to_datetime(df["trans_date"])`
       - Aggregate by `(area_name_en, prop_type_en)` per month using `resample('ME')`:
         - `volume` = count of transactions
         - `median_price` = median of actual_worth
         - `median_price_per_sqft` = median of meter_sale_price
         - `total_value` = sum of actual_worth
         - `price_p25` = 25th percentile of actual_worth
         - `price_p75` = 75th percentile of actual_worth
       - Compute YoY change: group by (area, prop_type), shift 12 months, calculate percentage change. If insufficient history, set to None.
       - Compute MoM change: shift 1 month, calculate percentage change.
       - Output records as: `[{source: "dld-sales", measurement_date, metric_name, value, available_date}]`
         where metric_name encodes area, property_type, and metric. Format: `{area}|{prop_type}|{metric}` (e.g., "Dubai Marina|Villa|median_price")
       - Both measurement_date (transaction month) and available_date (collectedAt) stored per NORM-02

    7. **normalize_ejari.py** — Ejari rental normalization:
       - Same stdin pattern, same CSV
       - Filter to rentals: `df[df["trans_group_en"] == "Rent"]`
       - Aggregate by `(area_name_en, prop_type_en)` per month:
         - `rental_volume` = count
         - `avg_rent` = mean of actual_worth
         - `avg_rent_per_sqft` = mean of meter_sale_price
       - Derive `renewal_rate`: requires comparing transaction counts to prior period. Approximation: if trans_group_en has sub-types for new vs renewal, use those. Otherwise, compare volume to prior month (increase suggests renewals).
       - Derive `rent_yoy_change`: YoY percentage change of avg_rent
       - Output in same metric_name format: `{area}|{prop_type}|{metric}`
