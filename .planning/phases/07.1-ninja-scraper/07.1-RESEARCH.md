# Phase 7.1: Ninja Scraper - Research

**Researched:** 2026-03-12
**Domain:** General-purpose Python web scraping infrastructure
**Confidence:** HIGH

## Summary

Phase 7.1 builds a production-grade, general-purpose Python web scraping engine (`@lobsec/scraper`) as a reusable capability for the lobsec ecosystem. This replaces the failed TypeScript collectors from Phase 7, where all 7 collectors encountered anti-bot defenses (WAF blocks, CAPTCHA, CloudFront 403).

The engine combines Crawlee for Python (orchestration, concurrency, retry logic), Patchright (undetected Playwright fork for stealth), and FastAPI (service API layer) with declarative YAML mission specifications. It's designed as a general-purpose scraper that UAE RE collectors consume as clients, not a UAE-specific tool.

**Primary recommendation:** Use Crawlee's PlaywrightCrawler with Patchright as the browser backend, conservative concurrency defaults (max_concurrency=2), exponential backoff with jitter, and FastAPI's built-in BackgroundTasks for request handling. Deploy as an always-running systemd service with isolated venv and token authentication.

### Pattern 1: Firecrawl-Inspired API Design

**What:** FastAPI endpoints mimic Firecrawl's /scrape, /crawl, /missions pattern with JSON schema support

**When to use:** Consistent API surface for single-page scrapes (/scrape), multi-page crawls (/crawl), and mission management (/missions)

**Example:**
```python
# Source: User CONTEXT.md + https://docs.firecrawl.dev/api-reference/endpoint/scrape
from fastapi import FastAPI, BackgroundTasks, Depends
from pydantic import BaseModel, HttpUrl

app = FastAPI()

class ScrapeRequest(BaseModel):
    url: HttpUrl
    format: str = "json"  # json, html, markdown, screenshot
    schema: dict | None = None  # JSON schema for extraction

class ScrapeResponse(BaseModel):
    success: bool
    data: dict | None
    error: str | None
    duration_ms: int

@app.post("/scrape", response_model=ScrapeResponse)
async def scrape_endpoint(
    request: ScrapeRequest,
    background_tasks: BackgroundTasks,
    token: str = Depends(verify_token)
):
    """Single-page scrape with immediate response."""
    # Execute scrape synchronously (Crawlee handles timeout)
    result = await run_scrape(request.url, request.format, request.schema)
    return result

class CrawlRequest(BaseModel):
    mission_name: str  # References missions/dld-sales.yml
    params: dict = {}  # Mission-specific parameters

class CrawlResponse(BaseModel):
    job_id: str
    status: str  # queued, running, completed, failed
    message: str

@app.post("/crawl", response_model=CrawlResponse)
async def crawl_endpoint(
    request: CrawlRequest,
    background_tasks: BackgroundTasks,
    token: str = Depends(verify_token)
):
    """Multi-page crawl with background execution."""
    job_id = generate_job_id()
    background_tasks.add_task(run_mission, job_id, request.mission_name, request.params)
    return CrawlResponse(job_id=job_id, status="queued", message=f"Mission {request.mission_name} queued")

@app.get("/crawl/{job_id}")
async def get_crawl_status(job_id: str, token: str = Depends(verify_token)):
    """Check background crawl status."""
    # Query job state from Crawlee storage
    return {"job_id": job_id, "status": "running", "progress": "3/10 pages"}
```

# engine/mission.py
from pydantic import BaseModel, HttpUrl, Field
from typing import Literal

class RetryConfig(BaseModel):
    max_attempts: int = Field(ge=1, le=10)
    initial_delay_ms: int = Field(ge=100)
    max_delay_ms: int = Field(ge=1000)
    backoff_multiplier: float = Field(ge=1.0, le=5.0)
    jitter: bool = True
    skip_on_403: bool = False

class Mission(BaseModel):
    name: str
    description: str
    type: Literal["http_download", "browser_scrape", "api_call"]
    frequency: Literal["daily", "weekly", "monthly", "quarterly"]
    priority: int = Field(ge=1, le=5)
    source: dict
    extraction: dict
    output: dict
    retry: RetryConfig = Field(default_factory=RetryConfig)
    timeout_ms: int = Field(ge=5000, le=3600000)

def load_mission(path: str) -> Mission:
    with open(path, "r") as f:

### Pattern 3: Patchright Integration with Crawlee

**What:** Use Patchright as browser backend for PlaywrightCrawler by overriding browser instance

**When to use:** All browser_scrape missions requiring stealth (Bayut, PropertyFinder, ADREC)

**Example:**
```python
# stealth/browser.py
# Source: https://github.com/Kaliiiiiiiiii-Vinyzu/patchright-python
from patchright.async_api import async_playwright
from crawlee.crawlers import PlaywrightCrawler, PlaywrightCrawlingContext

async def get_patchright_browser():
    """Launch Patchright Chromium with stealth config."""
    playwright = await async_playwright().start()
    browser = await playwright.chromium.launch(
        headless=True,
        args=[
            "--disable-blink-features=AutomationControlled",
            "--disable-dev-shm-usage",
            "--no-sandbox"
        ]
    )
    return browser, playwright

async def run_stealth_mission(mission: Mission):
    """Execute browser mission with Patchright."""
    browser, playwright = await get_patchright_browser()

    try:
        crawler = PlaywrightCrawler(
            max_concurrency=mission.concurrency.max_concurrent,
            headless=True,
            browser_type="chromium"
        )

        # Override Crawlee's browser with Patchright instance
        # NOTE: Crawlee's browser_pool may need custom plugin
        # Alternative: use Patchright page directly without Crawlee's browser pool

        @crawler.router.default_handler
        async def handler(context: PlaywrightCrawlingContext) -> None:
            # Use context.page from Patchright browser
            await context.page.goto(mission.source.url)
            # Extract data per mission.extraction.selectors
            data = await extract_data(context.page, mission.extraction)
            await context.push_data(data)

        await crawler.run([mission.source.url])
    finally:
        await browser.close()
        await playwright.stop()
```

**NOTE:** Crawlee's PlaywrightBrowserPlugin may need custom override. Research during implementation whether to:
1. Extend PlaywrightBrowserPlugin to use Patchright
2. Use Patchright pages directly and bypass Crawlee's browser pool
3. Contribute Patchright integration upstream to Crawlee

### Pattern 4: Exponential Backoff with Jitter

**What:** Retry failed requests with increasing delays + randomization to avoid retry storms

**When to use:** All HTTP and browser operations. Critical for rate-limited sources.

**Example:**
```python
# utils/retry.py
# Source: https://substack.thewebscraping.club/p/rate-limit-scraping-exponential-backoff
import random
import asyncio
from tenacity import (
    retry,
    stop_after_attempt,
    wait_exponential,
    retry_if_exception_type,
    before_sleep_log
)
import structlog

logger = structlog.get_logger()

def exponential_backoff_with_jitter(
    max_attempts: int,
    initial_delay_ms: int,
    max_delay_ms: int,
    multiplier: float = 2.0
):
    """Retry decorator with exponential backoff + jitter."""
    return retry(
        stop=stop_after_attempt(max_attempts),
        wait=wait_exponential(
            multiplier=multiplier / 1000,  # Convert to seconds
            min=initial_delay_ms / 1000,
            max=max_delay_ms / 1000
        ),
        retry=retry_if_exception_type((httpx.HTTPError, asyncio.TimeoutError)),
        before_sleep=before_sleep_log(logger, logging.WARNING),
        reraise=True
    )

# Add jitter manually after tenacity's exponential calculation
async def retry_with_jitter(func, mission: Mission, *args, **kwargs):
    """Wrap function with mission-specific retry config."""
    retry_config = mission.retry

    for attempt in range(retry_config.max_attempts):
        try:
            return await func(*args, **kwargs)
        except Exception as e:
            if attempt == retry_config.max_attempts - 1:
                raise

            # Check skip conditions
            if retry_config.skip_on_403 and isinstance(e, httpx.HTTPStatusError) and e.response.status_code == 403:
                logger.warning("403 detected, skipping retries per mission config", mission=mission.name)
                raise

            # Calculate delay with jitter
            base_delay = retry_config.initial_delay_ms * (retry_config.backoff_multiplier ** attempt)
            delay = min(base_delay, retry_config.max_delay_ms)

            if retry_config.jitter:
                # Add ±25% jitter to avoid thundering herd
                jitter_range = delay * 0.25
                delay = delay + random.uniform(-jitter_range, jitter_range)

            logger.info(
                "Retrying after delay",
                attempt=attempt + 1,
                max_attempts=retry_config.max_attempts,
                delay_ms=int(delay),
                error=str(e)
            )

            await asyncio.sleep(delay / 1000)
```

### Pattern 5: Custom Crawlee Storage Client

**What:** Override default Crawlee storage to save to `/opt/lobsec/data/raw/` instead of `./storage/`

**When to use:** All missions. Ensures output lands in fscrypt-encrypted directory.

**Example:**
```python
# engine/storage.py
# Source: https://crawlee.dev/python/docs/guides/storage-clients
from crawlee.storages import FileSystemStorageClient
from pathlib import Path

class LobsecStorageClient(FileSystemStorageClient):
    """Custom storage client writing to /opt/lobsec/data/raw/."""

    def __init__(self, base_dir: str = "/opt/lobsec/data/raw"):
        super().__init__(persist_storage=True)
        self.base_dir = Path(base_dir)

    async def get_dataset_dir(self, dataset_id: str) -> Path:
        """Override dataset directory."""
        return self.base_dir / dataset_id

    async def get_key_value_store_dir(self, kvs_id: str) -> Path:
        """Override KVS directory."""
        return self.base_dir / "kvs" / kvs_id

# Use in crawler
from crawlee.configuration import Configuration

config = Configuration(
    storage_client=LobsecStorageClient()
)

crawler = PlaywrightCrawler(configuration=config)
```

### Anti-Patterns to Avoid

- **Hardcoding source URLs in Python code:** Use YAML missions instead. Code should be generic.
- **Synchronous blocking in FastAPI handlers:** Use async/await or BackgroundTasks. Never `time.sleep()`.
- **Retrying 403/CAPTCHA immediately:** Exponential backoff won't help. Detect and skip with `skip_on_403: true`.
- **High concurrency for stealth missions:** `max_concurrency=2` is safer. Speed kills stealth.
- **Using Playwright directly instead of Patchright:** Playwright has CDP leaks. Always use Patchright for public sites.
- **Global exception handlers hiding failures:** Let missions fail loudly. Log to structlog, alert to Telegram.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| **Request queue management** | Custom job queue with SQLite | Crawlee's RequestQueue | Handles deduplication, persistence, priority, retries. Tested with 100k+ URLs. |
| **Browser pool lifecycle** | Manual Playwright launch/close | Crawlee's PlaywrightBrowserPlugin | Auto-scales browsers based on CPU/memory, handles crashes, reuses contexts. |
| **Retry with backoff** | Custom retry loop | tenacity decorators + Crawlee's AutoscaledPool | Handles jitter, max attempts, exponential calculation, logging. Already debugged. |
| **HTTP client with retry** | requests + custom retry | httpx with tenacity | Async-native, connection pooling, timeout handling, follows redirects. |
| **YAML schema validation** | Manual dict checking | Pydantic models | Type checking, nested validation, JSON schema export, error messages. |
| **API authentication** | Custom token checking | FastAPI Depends + HTTPBearer | Built-in OAuth2/JWT support, dependency injection, automatic 401 responses. |
| **Structured logging** | print() or stdlib logging | structlog | JSON output, context binding, async-safe, integrates with audit trail. |

**Key insight:** Web scraping has deceptively hard edge cases (duplicate URLs, browser crashes, rate limits, connection timeouts, partial failures). Crawlee and FastAPI have solved these. Don't reinvent — compose.

## Common Pitfalls

### Pitfall 1: Patchright/Crawlee Browser Integration

**What goes wrong:** Crawlee's PlaywrightBrowserPlugin may not directly support Patchright's custom browser instances. Attempting to pass Patchright browser to Crawlee's browser_pool can cause type mismatches or context issues.

**Why it happens:** Patchright is a fork with slightly different initialization paths. Crawlee expects vanilla Playwright API.

**How to avoid:**
1. **Option A:** Use Patchright pages directly, bypass Crawlee's browser pool. Lose auto-scaling but gain full stealth control.
2. **Option B:** Create custom PlaywrightBrowserPlugin subclass that launches Patchright. More complex but preserves Crawlee features.
3. **Option C:** Contribute Patchright support upstream to Crawlee (long-term).

Start with Option A for MVP. Evaluate Option B if browser pool becomes bottleneck.

**Warning signs:** ImportError on Patchright classes, browser.new_context() failing with "browser not connected", Crawlee complaining about browser type.

### Pitfall 2: BackgroundTasks for Long-Running Scrapes

**What goes wrong:** FastAPI's BackgroundTasks run in the same process. If a mission takes 15+ minutes or crashes, it can block other requests or leave zombie tasks.

**Why it happens:** BackgroundTasks are lightweight, not distributed. No task queue, no persistence.

**How to avoid:**
- **For MVP:** Missions timeout at 10 minutes (600s). Enforce with mission.timeout_ms.
- **If scrapes exceed 10min:** Consider Celery + Redis for Phase 8+.
- **Monitor task count:** If BackgroundTasks queue grows beyond 10, log warning.

**Validation:** Test with 30-minute timeout mission. Ensure it gets killed and reports failure.

**Warning signs:** uvicorn worker timeouts, memory growth during long missions, HTTP 504 on /crawl endpoint.

### Pitfall 3: YAML Schema Evolution Without Versioning

**What goes wrong:** Mission YAML schema changes break existing mission files. Old missions fail validation after code update.

**Why it happens:** No schema version field in YAML.

**How to avoid:**
- Add `schema_version: 1.0` to every mission YAML.
- Pydantic Mission model checks version and applies migrations.
- Log deprecation warnings for old schemas, hard fail on unsupported versions.

**Example:**
```python
class Mission(BaseModel):
    schema_version: str = "1.0"
    name: str
    # ... rest of schema

    @model_validator(mode="before")
    def migrate_schema(cls, values):
        version = values.get("schema_version", "1.0")
        if version == "1.0":
            return values
        elif version == "0.9":
            # Migrate 0.9 -> 1.0
            logger.warning("Migrating mission from schema 0.9 to 1.0")
            values["schema_version"] = "1.0"
            # Apply transformations
            return values
        else:
            raise ValueError(f"Unsupported mission schema version: {version}")
```

**Warning signs:** Pydantic validation errors on existing missions after update, missing fields, unexpected defaults.

### Pitfall 4: fscrypt Access from systemd Service

**What goes wrong:** systemd service can't write to `/opt/lobsec/data/raw/` if directory is fscrypt-encrypted and service doesn't unlock it.

**Why it happens:** fscrypt requires explicit unlock. Service starts before unlock happens.

**How to avoid:**
- Ensure `/opt/lobsec/data/` is unlocked in systemd unit `ExecStartPre`.
- Or store raw data in non-encrypted staging area, move to fscrypt directory in separate process.
- Verify write permissions: service runs as `lobsec` user, directory owned by `lobsec:lobsec`.

**Validation:** Test scraper startup with fresh boot. Check journalctl for permission denied errors.

**Warning signs:** "Permission denied" writing to output path, empty output files, OSError on mkdir.

### Pitfall 5: Mission Timeouts vs Crawler Timeouts

**What goes wrong:** Crawlee's internal timeout (page.goto, waitForSelector) can be shorter than mission.timeout_ms, causing mission to fail early without proper error message.

**Why it happens:** Multiple timeout layers: FastAPI request timeout, mission timeout, Crawlee timeout, Playwright timeout.

**How to avoid:**
- Set hierarchy: `playwright_timeout < crawlee_timeout < mission_timeout < fastapi_timeout`.
- Example: Playwright 30s, Crawlee 5min, Mission 10min, FastAPI 15min.
- Wrap Crawlee calls with asyncio.timeout(mission.timeout_ms).

**Example:**
```python
async def run_mission(mission: Mission):
    async with asyncio.timeout(mission.timeout_ms / 1000):
        crawler = PlaywrightCrawler(
            request_handler_timeout_secs=mission.timeout_ms / 1000 - 60  # Leave 1min buffer
        )
        await crawler.run([mission.source.url])
```

**Warning signs:** Missions timing out at unexpected intervals, "TimeoutError" without mission name in logs.

### Pitfall 6: Browser Binary Installation in Deployment

**What goes wrong:** `patchright install chromium` downloads browsers to user-specific directory. systemd service user may not have browser installed.

**Why it happens:** Playwright/Patchright browser binaries stored in `~/.cache/ms-playwright` by default.

**How to avoid:**
- Run `patchright install chromium` as `lobsec` user during deployment.
- Or set `PLAYWRIGHT_BROWSERS_PATH=/opt/lobsec/scraper-venv/browsers` in systemd unit.
- Add `ExecStartPre=/opt/lobsec/scraper-venv/bin/patchright install chromium --skip-if-exists` to service file.

### Exponential Backoff with Jitter

```python
# Source: https://substack.thewebscraping.club/p/rate-limit-scraping-exponential-backoff
import random
import asyncio

async def fetch_with_retry(url: str, max_attempts: int = 3):
    for attempt in range(max_attempts):
        try:
            response = await httpx.get(url, timeout=30.0)
            response.raise_for_status()
            return response
        except httpx.HTTPStatusError as e:
            if e.response.status_code == 429:
                # Rate limited - exponential backoff with jitter
                base_delay = 2 ** attempt  # 1s, 2s, 4s
                jitter = random.uniform(0, base_delay * 0.25)
                delay = base_delay + jitter

                # Check Retry-After header if present
                if "Retry-After" in e.response.headers:
                    delay = max(delay, int(e.response.headers["Retry-After"]))

                await asyncio.sleep(delay)
            else:
                raise

    raise Exception(f"Failed after {max_attempts} attempts")
```

async def verify_token(credentials: HTTPAuthorizationCredentials = Depends(security)) -> str:
    """Verify Bearer token from HSM."""

## State of the Art

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| Selenium + undetected-chromedriver | Playwright + Patchright | 2024-2025 | Playwright faster, more stable. Patchright patches at source level (not runtime injection) — harder to detect |
| Scrapy (Twisted callbacks) | Crawlee (async/await) | 2023-2024 | Native asyncio more readable, better concurrency control, integrates with FastAPI |
| requests library | httpx | 2022+ | Async/await support, HTTP/2, connection pooling, better timeout handling |
| Custom retry logic | tenacity decorators | Ongoing | Declarative retry config, less boilerplate, tested library |
| Firecrawl (SaaS) | Self-hosted Crawlee + Patchright | 2024+ | Firecrawl pioneered /scrape, /crawl API design but is paid SaaS. Ninja Scraper replicates pattern open-source |

**Deprecated/outdated:**
- **Scrapy**: Still maintained but callback-based (not async/await). Community shifting to Crawlee.
- **Selenium**: Still works but slower than Playwright, harder to make undetectable.
- **BeautifulSoup-only scraping**: No JS rendering. Most modern sites need browser automation.
- **requests library for async**: Use httpx. requests is sync-only.

## Open Questions

1. **Patchright Browser Pool Integration**
   - What we know: Crawlee's PlaywrightBrowserPlugin manages browser lifecycle. Patchright is drop-in API replacement but different initialization.
   - What's unclear: Can Crawlee's browser pool use Patchright instances directly? Or must we bypass pool?
   - Recommendation: Start with manual Patchright pages (bypass pool). If browser pool needed, create custom plugin in Wave 2.

2. **Mission Execution Model**
   - What we know: FastAPI BackgroundTasks sufficient for <10min tasks. Celery needed for distributed, long-running tasks.
   - What's unclear: Will UAE RE missions stay under 10min? Bayut scraping 50+ areas could hit 15-20min.
   - Recommendation: Start with BackgroundTasks + 10min timeout. Add Celery in Phase 8 if needed. Monitor task duration in production.

3. **TS-to-Python Integration Point**
   - What we know: TS CollectorRegistry becomes thin HTTP client. Python scraper is separate service.
   - What's unclear: Should TS wait synchronously for /scrape or poll /crawl/{job_id}? What's UX for user triggering collection?
   - Recommendation: `/scrape` for simple CSV downloads (DLD, DEWA) — synchronous. `/crawl` for browser missions (Bayut, ADREC) — async with polling. TS polls every 5s with max 10min timeout.

4. **Raw Data Format Consistency**
   - What we know: Existing normalize_*.py scripts expect CSV or JSON at specific paths.
   - What's unclear: Should scraper output match existing format exactly? Or can we improve (e.g., add metadata JSON)?
   - Recommendation: Phase 7.1 matches existing format exactly (CSV for DLD, JSON for Bayut). Phase 8+ can add metadata sidecar files (scrape_metadata.json with timestamp, mission version, row count).

5. **HSM Token Storage for Scraper**
   - What we know: Pattern is `pkcs11-tool --write-object`, token name in HSM, environment variable in systemd.
   - What's unclear: Token name? `scraper-auth-token` or `ninja-scraper-token`?
   - Recommendation: Use `scraper-auth-token` (consistent with `gateway-auth-token`, `proxy-auth-token`). Store in .env as `SCRAPER_AUTH_TOKEN`.
