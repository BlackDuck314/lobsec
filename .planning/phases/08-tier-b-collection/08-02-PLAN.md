    Create 2 Python normalization modules following the exact normalize_dewa.py pattern (stdin/stdout JSON bridge).

    **normalize_jobs.py** (COLL-11 — handles all 4 job platforms):

    Per user decision: Store aggregated counts per sector/seniority weekly — total_postings, postings_by_sector, postings_by_seniority, median_salary_range. NOT individual listings.

    Functions:
    - `classify_seniority(salary_min: int, salary_max: int) -> str`: Junior (< 10K), Mid (10-25K), Senior (25-50K), Executive (> 50K AED/month). Returns "unspecified" if both are 0.
    - `classify_sector(job_title: str) -> str`: Keyword-based classification into tech, finance, hospitality, construction, healthcare, retail, other. Use keyword lists from 08-RESEARCH.md.
    - `normalize_jobs(data: dict, collected_at: str, platform: str) -> list[dict]`:
      - Input: JSON with job listings array from one platform
      - Aggregate: count total postings, group by sector (classify from job titles), group by seniority (classify from salary ranges)
      - Compute median_salary_range from available salary data
      - Output metrics:
        - `uae|{platform}_total_postings` (e.g., uae|linkedin_total_postings)
        - `uae|{platform}_postings_tech`, `uae|{platform}_postings_finance`, etc. (per sector)
        - `uae|{platform}_postings_junior`, `uae|{platform}_postings_mid`, etc. (per seniority)
        - `uae|{platform}_median_salary` (if salary data available)
      - measurement_date: start of week (Monday) from collection date
    - `main()`: Reads stdin JSON, detects platform from source field (linkedin-jobs -> linkedin, bayt-jobs -> bayt, etc.), calls normalize_jobs(), outputs to stdout.

    Handle graceful failure: if platform returned empty/blocked (403 response means empty data), return empty metrics list (will trigger empty collection warning via orchestrator).

    **normalize_salary.py** (COLL-12 — handles all 3 salary firms):

    Functions:
    - `extract_salary_tables(pdf_path: str, firm: str) -> dict`:
      - Use pdfplumber to open PDF and extract tables
      - Target pages with salary data (typically 5-20 pages into the report)
      - Table detection: headers containing "Salary", "Compensation", "Role", "Position"
      - Extract: role name, seniority level, salary_min, salary_max, median_salary
      - Return dict with extracted salary data by role/seniority
    - `normalize_salary(data: dict, collected_at: str, firm: str) -> list[dict]`:
      - Input: extracted salary data from PDF
      - Output metrics per seniority bracket:
        - `uae|{firm}_median_salary_junior` (e.g., uae|cooper_fitch_median_salary_junior)
        - `uae|{firm}_median_salary_mid`
        - `uae|{firm}_median_salary_senior`
        - `uae|{firm}_median_salary_executive`
        - `uae|{firm}_sample_size` (number of roles surveyed)
      - measurement_date: January 1st of report year (annual data)
    - `main()`: Reads stdin JSON, detects firm from source field, loads PDF via pdfplumber, normalizes, outputs to stdout.
    - Per CONTEXT: when pdfplumber extraction fails, output descriptive error for Telegram manual-entry fallback including PDF path and required fields.

    Both modules: import their pandera schema validators, follow error output pattern, handle edge cases (missing salary data, empty listings, malformed PDF tables).

    **schemas/jobs_schema.py**: Validate raw JSON structure (must have listings array or total_count field).
    **schemas/salary_schema.py**: Validate PDF extraction result (must have at least 1 salary entry).
