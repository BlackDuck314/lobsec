# Plan 27-03: Weekly Digest Timer + TLS Lifecycle Fix

**Requirements:** REPAIR-04, REPAIR-05
**Estimated scope:** Small — systemd service fixes, verification

## Context

### Weekly Digest (REPAIR-04)
The `lobsec-weekly-digest.timer` fires every Monday 04:00 UTC but the service fails because `TELEGRAM_BOT_TOKEN` is missing from its environment. The service loads only `/opt/lobsec/boot/pin.env` (HSM PIN, Gmail user, GitHub user) and the script sources `/opt/lobsec/.env` (UAE data dir, scraper token). Neither contains `TELEGRAM_BOT_TOKEN`.

The token lives in `/opt/lobsec/.openclaw/.env`, generated by `hsm-extract-credentials.sh` during `lobsec.service` startup. The digest service simply doesn't source this file.

Same issue likely affects `lobsec-monthly-report.service` and `lobsec-alerts.service`.

### TLS Lifecycle (REPAIR-05)
`PartOf=lobsec.service` was added to `lobsec-proxy.service` earlier today. Need to verify it works — when gateway restarts (regenerating TLS certs), proxy should auto-restart and pick up new certs.

## Steps

### 1. Fix weekly digest service environment

Edit `/etc/systemd/system/lobsec-weekly-digest.service` — add EnvironmentFile for OpenClaw credentials:

```ini
[Service]
...
EnvironmentFile=/opt/lobsec/boot/pin.env
EnvironmentFile=/opt/lobsec/.openclaw/.env
```

Also update the repo copy at `/root/lobsec/deploy/lobsec-weekly-digest.service`.

### 2. Fix monthly report and alerts services (same issue)

Check and fix these services for the same missing env:
- `/etc/systemd/system/lobsec-monthly-report.service`
- `/etc/systemd/system/lobsec-alerts.service`

Add `EnvironmentFile=/opt/lobsec/.openclaw/.env` to each.

Update repo copies in `/root/lobsec/deploy/`.

### 3. Fix digest log file permissions

The log file `/opt/lobsec/logs/digest.log` is owned by root but the service runs as `lobsec`:

```bash
chown lobsec:lobsec /opt/lobsec/logs/digest.log
```

### 4. Reload and test weekly digest

```bash
systemctl daemon-reload
systemctl start lobsec-weekly-digest.service
journalctl -u lobsec-weekly-digest -n 30 --no-pager
```

Verify:
- Service completes successfully (exit code 0)
- Telegram message received with weekly digest content
- No "No TELEGRAM_BOT_TOKEN" errors

### 5. Verify TLS cert lifecycle

Test that proxy auto-restarts with gateway:

```bash
# Check proxy is running
systemctl is-active lobsec-proxy

# Check PartOf= is recognized
systemctl show lobsec-proxy | grep PartOf

# Restart gateway (this regenerates TLS certs)
systemctl restart lobsec

# Wait 5 seconds, check proxy restarted too
sleep 5
systemctl is-active lobsec-proxy
journalctl -u lobsec-proxy -n 10 --no-pager

# Verify proxy can reach Anthropic (the primary backend)
curl -sk -H "Authorization: Bearer <gateway-token>" \
  -H "Content-Type: application/json" \
  -d '{"model":"claude-haiku-4-5-20251001","messages":[{"role":"user","content":"ping"}],"max_tokens":10}' \
  https://127.0.0.1:18790/v1/messages
```

Confirm:
- Proxy restarted within seconds of gateway restart
- Proxy TLS handshake works (no cert mismatch)
- Anthropic API call succeeds through proxy

### 6. Commit service file changes

Stage and commit the updated service files.

## Success Criteria

1. `lobsec-weekly-digest.service` runs successfully with Telegram message delivered
2. `lobsec-monthly-report.service` and `lobsec-alerts.service` have correct environment
3. `/opt/lobsec/logs/digest.log` owned by lobsec user
4. Gateway restart triggers proxy restart (PartOf= verified)
5. Post-restart proxy serves requests successfully (no TLS mismatch)

## Risk

- Low risk — systemd EnvironmentFile changes are straightforward
- Gateway restart will briefly interrupt bot service (~5 seconds)
- If `.openclaw/.env` doesn't exist yet (e.g., after LUKS unlock but before first lobsec start), digest will still fail — acceptable edge case
